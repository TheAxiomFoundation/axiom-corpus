The corpus resolver no longer follows a symlinked file at a protected corpus path to its target. The link names its own path, so when a lock names that path, the `io` readers (`load_provisions`, `load_source_inventory`), `fetch_locked_file`, `resolve_corpus_path`, `require_materialized` and fetch refuse it: a dangling link no longer reads an absent locked file as an empty scope, and a link to a cache object or another corpus file is no longer taken for the locked file. Checkout spellings that `realpath` leaves apart (a case variant on APFS, the `/System/Volumes/Data` firmlink) now resolve as well, so an unfetched provisions file reached through one is fetched instead of loading as empty.
