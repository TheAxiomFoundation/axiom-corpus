Retry transient R2 read errors (HTTP 429, 500, 502, 503 and 504, throttling codes, timeouts, dropped connections) inside each read, up to 8 HTTP requests per key per read with botocore's own retries off for reads, using jittered exponential backoff that honours `Retry-After`; resume a body that breaks mid-stream from the next byte; read one object at a time per store; and fetch in random order. A throttled or dropped read is retried before a fetch fails, and a fetch still fails once an object's budget is spent. Missing objects, refusals, TLS failures and bytes that fail verification still fail at once within a pass.
