Retry transient R2 read errors (throttling, 5xx, timeouts, dropped connections) up to 8 HTTP requests per object, with jittered exponential backoff that honours `Retry-After`; resume a body that breaks mid-stream from the next byte; read one object at a time per store; and fetch in random order. A throttled or dropped read is retried before a fetch fails, and a fetch still fails once an object's budget is spent. Missing objects, refusals, TLS failures and bytes that fail verification still fail at once.
