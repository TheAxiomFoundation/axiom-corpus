`scripts/build_ccdf_state_plan_manifests.py` now addresses a queue row by its `target_manifest` instead of its `jurisdiction`, and cannot destroy a row by rebuilding. `manifests/ccdf-agent-queue.yaml` does not hold one row per jurisdiction: three rows carry `us` (the ACF plan directory, 45 CFR part 98, the CCDBG statute) and two carry `us-in` (the ACF-118 plan and the FSSA CCDF Policy Manual), so the dict comprehension in `refresh_rows_only` silently kept whichever row the file listed last, and `--only in` would have written the plan row's status, scope, source and target manifest onto the policy-manual row while leaving the plan row untouched. That function is retired: `--only` is now the older name of `--only-plan-rows`, which selects by target manifest through the new `one_row` helper and refuses unless exactly one row matches. The full rebuild moves behind `--rebuild` — a bare invocation now names no pass and writes nothing — and carries through every row the ACF index does not supply, each row's `additional_families` (51 appendix, amendment, rate-schedule and wave-6 bundle blocks), each row's committed `target_scope.version` and each manifest's committed `source_as_of`, so it no longer drops the two leading `us` rows, overwrites the third with the directory row's fields, or restamps 44 manifests it did not re-read. `refuse_if_rows_lost` refuses the write outright if a row or a family block would be lost. A rebuild of the committed resolutions now reproduces every committed plan manifest byte for byte; it corrects one stale derived count, `index_inventory.families.state_plan_links.taken`, from 46 to the 47 plan rows actually taken.
