The release gate's scope_monotonicity check no longer fails a release that keeps a grandfathered version key that does not parse as YYYY-MM-DD-… (us-ky form `2026-740-es`) and adds dated versions beside it: a version both sides keep is unchanged, so only the versions that differ are ordered. Publication recency is still required, a new malformed version still fails, and keeping only the grandfathered key while dropping ordered active versions still fails.
