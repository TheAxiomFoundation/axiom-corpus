`scripts/sign_release_scopes.sh` now commits the signed manifests of the draft selector's unreleased scopes and no others. It used to stage everything under `.axiom/ingest-manifests`, so an untracked manifest of any other scope went into its "Sign <name> scopes" commit, which it made even when every unreleased scope was already signed. The header's exception for a fix that changes, adds or removes an artifact of a scope that already has a manifest no longer applies to manifests the script signed itself on the branch: step 2 signs such a scope again. Before it does, the manifest must pass four checks. It is untracked or absent at the merge base with both origin/main and main. It records the script's own command, no reasoning logs and no deleted files. Its files are exactly the scope's artifacts in the commit it was signed against, not a hand-picked `--file` list. And it no longer matches, either because its files or their sha256s are not the scope's artifacts or because that commit has left HEAD's history. An untracked manifest that is not readable JSON is signed again as well. Any other manifest, including one committed on main or signed in an ingest PR, is never replaced. The replacement is signed aside, because the signer needs a clean tracked tree, and moved into place just before the sign commit; a run that stops in between puts the committed copy back, retrying once as the unstage does. The script cannot mark an artifact deleted, so when a scope it would sign removes an artifact that main has, it stops before staging anything and says how to sign that scope by hand. Step 1 now also refuses a symlinked artifact: the signer records the file a link points to, so `guard-ingested` never finds the link's own path.

Re-signing requires an exact match with the rebuild command selected for the scope, including its manifest path and version-specific command form. Foreign custom-path and consolidation commands retain their original provenance.
