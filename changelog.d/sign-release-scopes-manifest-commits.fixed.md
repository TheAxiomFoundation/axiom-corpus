`scripts/sign_release_scopes.sh` now commits the signed manifests of the draft selector's unreleased scopes and no others. It used to stage everything under `.axiom/ingest-manifests`, so an untracked manifest of any other scope went into its "Sign <name> scopes" commit, which it made even when every unreleased scope was already signed. The header's exception for a fix that changes, adds or removes an artifact of a scope that already has a manifest now covers only manifests the script did not sign. When the script signed the manifest itself on the branch, it is no longer deleted by hand: step 2 signs that scope again. That requires the manifest to be untracked or committed after the merge base with main, to record the script's own command and no reasoning logs or deleted files, and to no longer match, either because its files or their sha256s are not the scope's artifacts or because the commit it was signed against has left HEAD's history. An untracked manifest that is not readable JSON is signed again as well. A manifest committed on main or signed in an ingest PR is never replaced. The replacement is signed aside, because the signer needs a clean tracked tree, and moved into place just before the sign commit; a run that stops in between puts the committed copy back.
