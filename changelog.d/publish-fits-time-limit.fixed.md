Publication of large named releases now fits the CI job: `scripts/publish_corpus.py` stages and reads back content-addressed R2 objects on a bounded thread pool (`--r2-workers`, default 16) instead of one object at a time, emits a flushed, timestamped progress line at the start and end of every publication phase with object/scope/row counts and elapsed seconds, and the `publish` workflow job timeout is raised to GitHub's 360-minute maximum. Every object is still snapshotted, hashed, conditionally written, read back, and byte-and-hash verified individually; a 536-scope, 17,000-object release that was killed at 120 minutes with no log output is now expected to finish in roughly 25 to 35 minutes.
