A worktree whose corpus directories link to another checkout's no longer reads a file only its own lock names as an empty scope. The resolver used to consult only the other checkout's lock there, so `load_provisions` returned no rows for an unfetched file that only the worktree's lock names, and `require_materialized` and `ensure_corpus_paths` passed over it. On 2026-10-14 both live sharing worktrees held 633 such entries. Every helper now checks every lock that applies to a path. The checkout that names a part of the path still decides what is fetched there, and fetch still writes into that checkout. The lock of a checkout the path passes through by a symlink, and of the place a link leads to, must also find its files in place, or the helper refuses, naming both checkouts and the link. A path above a sharing link, such as the worktree's `data/corpus`, now reads the linked checkout's lock for the part below the link. Before, it ignored a file only that lock names, while the linked directory itself refused it. With `repo` given, a path that another checkout names is now checked there instead of being skipped. `resolve_corpus_path` with `repo` takes a bare `data/corpus/...` path in that checkout, as the other helpers do. `ensure_corpus_scopes` and the CLI's input fetch follow the same rules, and the CLI now counts an absolute or bare input path through such a link. The CLI works in the checkout where `--base` stands (through a link, the checkout holding the link), so a worktree whose whole `data/corpus` links to another checkout's keeps its own lock, and a checkout without locks of its own still reads the locks its links lead to. `analytics` requires the versions it reads (by the path it reads, not the lock entry's name) under every lock that applies to its class directories, and `scripts/audit_us_release_publishability.py` counts an artifact as locked under any of them. If the linked checkout has not made the linked directory yet, so the link dangles, the files below it are still that checkout's to fetch. A source read, and a scope's sources directory made whole for a fetch, now include files that another checkout names through a link inside the directory. An explicit `repo` no longer names the corpus paths of a checkout nested in its corpus tree; the nested checkout does, as without `repo` (its other files stay the outer checkout's). A lock that fails to parse in a checkout a path passes through now raises instead of being skipped.
