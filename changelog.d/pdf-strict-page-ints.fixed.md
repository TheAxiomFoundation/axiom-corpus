PDF extraction now rejects a page filter (legacy `start_page` or `end_page`, or a `page_windows` bound) that is not a positive integer under the `single_block`, `numbered_sections` and `labeled_sections` segmentations, which read those filters. It also rejects an `ocr_dpi` that is not a positive integer, and the error names the key (for example `page_windows[1].end_page`). Before, `int()` read `true` as page 1, cut `2.5` to page 2 and parsed `"3"` as page 3. `ocr_dpi` is now checked for every PDF extraction, not only when OCR runs. Every tracked manifest already uses plain integers, so its extraction is unchanged.
