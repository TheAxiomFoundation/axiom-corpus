PDF extraction now rejects a legacy `start_page` or `end_page`, a `page_windows` bound or an `ocr_dpi` that is not a positive integer, and names the key in the error (for example `page_windows[1].end_page`). Before, `int()` read `true` as page 1, cut `2.5` to page 2 and parsed `"3"` as page 3. `ocr_dpi` is now checked for every PDF extraction, not only when a page needs OCR. Every tracked manifest already uses plain integers, so its extraction is unchanged.
