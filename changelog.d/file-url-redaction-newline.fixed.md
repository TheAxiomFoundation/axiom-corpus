`redact_file_urls` no longer stops at a newline. A URL parser drops tabs and newlines anywhere in a URL, so the text after a newline inside a `file:` URL is still its path, and a message that named such a URL, in a crafted key or field name say, kept that part of the path. The redaction now runs from the scheme to the quote or backtick that closes the URL's context, or to the end of the text.
