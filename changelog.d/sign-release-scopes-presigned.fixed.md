`scripts/sign_release_scopes.sh` no longer stops at its manifest commit when every unreleased scope in the draft selector already has a committed signed ingest manifest, as when the scopes were signed in their ingest PR. It logs that the sign commit is skipped and goes on to cut the selector. Its `guard-ingested` self-check now takes `origin/main` as its base, or `main` when `origin/main` shares no history with HEAD, instead of `HEAD~2`. Because `guard-ingested` diffs from the merge base, that covers every commit the branch adds, including a data commit left by an earlier stopped run; `HEAD~2` was the branch point only when the branch held exactly a data commit and a sign commit. When neither ref shares history with HEAD, the script skips the self-check and says CI will run it. A failing self-check now stops the script before it cuts the selector.
