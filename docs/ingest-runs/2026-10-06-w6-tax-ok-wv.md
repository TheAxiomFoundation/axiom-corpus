## Method

1. **Held already?** Every row was first matched against an index of the local corpus root for the 12 jurisdictions (every
   provisions and inventory file, plus the three scopes that are locked on main but not on local disk, read from their git
   blobs: `us-wi/form/2026-09-23-wi-schedule-sb-2025`, `us-wi/statute/2026-09-23-income-tax-subunits-chapter-71`,
   `us-va/regulation/2026-09-23-va-22vac40-601-snap`): `bundle_path`, the manifest `source_url` of the EXTRACT-MANIFEST rows and
   the bundle address (scheme, `www.` and case folded) against inventory `source_url`/`download_url`, and statute addresses by
   section number against the held statute scopes. Nine EXTRACT-MANIFEST rows are TY2025 documents of the wave-5 forms scopes
   (PR #716) or the 2025 Schedule SB scope; each was confirmed by sha256 (the 2026-10-06 download equals the held source file).
2. **Publisher probe.** One GET per address with the corpus user agent (341 + 5 addresses, one request at a time per host,
   0.5 s spacing, TLS verified against certifi plus the committed `data/certs/` intermediates). Every PDF's printed title, tax
   year, revision and page count were read from page 1 (`pdftotext`); every HTML page's title, `h1` and content root were read.
   The facts are the static tables of `scripts/build_w6_tax_ok_wv_manifests.py`.
3. **Manifests.** The generator writes one official-documents manifest per jurisdiction and class,
   `manifests/us-xx-income-tax-w6-{forms,guidance,statute,regulation,rulemaking}.yaml` (35 manifests, 291 documents), and
   `manifests/state-income-tax-chapters-w6-tax-ok-wv.yaml` (ORS chapter 315 and S.C. Code 59-2 through the state adapters). Version
   `2026-10-06-w6-income-tax-<family>-<st>` (the adapters append their scope suffix). `source_url` is the bundle address exactly
   wherever that address serves the document; the decisions file carries the join for every other row.
4. **Extraction.** `extract-official-documents` per manifest (states in parallel, one manifest at a time per state, so one host
   at a time), `extract-state-statutes` for the two chapters. Coverage checked for every scope: `complete: true`, 0 missing,
   0 extra, 0 duplicate citation paths; every inventory source file present (the SC adapter also keeps its native `statmast.html`
   index); `scripts/validate_citation_paths.py` on the 37 new provisions files: 1,302 records then, `RESULT: OK` (no uppercase,
   space, en-dash, page-N or truncated segments; 561 `block-N` rows, all per-heading rows of HTML pages).

Citation paths. New documents follow the 2026-09-10 / wave-5 convention: forms `us-xx/form/<agency>/ty<year>/<id>`
(agency tokens as in the released scopes: otc, dor, department-of-revenue, tax, ustc, vdt), guidance `us-xx/guidance/<publisher>/<slug>`,
bills and session laws `us-xx/statute/{bills,session-laws}/<session>/<bill-or-chapter>` (the OR 2026 session-law precedent),
statute sections in the jurisdiction's existing form (`us-ri/statute/44-33-3`, `us-vt/statute/32-6066`,
`us-wa/statute/82/82.08/82.08.0206`). EXTRACT-MANIFEST documents keep the May 2026 manifest's path with the citation-path slug
rule applied, because the old paths fail the grammar (underscores): `us-or/form/tax_forms/oregon.gov/dor/forms/formspubs/form-or-40-inst_101-040-1_2021`
becomes `us-or/form/tax-forms/oregon.gov/dor/forms/formspubs/form-or-40-inst-101-040-1-2021` (`citation_segment` on every segment;
the decisions file maps each bundle path to its new path). Prior versions of Utah Code sections take the same-number variant form
`us-ut/statute/59-10-1047--version-2023050320240101` (the publisher's version id).

Segmentation: PDFs `single_block` (root + `document-1`, the convention for state forms and booklets); HTML pages one row per
heading inside a per-publisher content root (`html_content_selector`); where the publisher prints its text in `div`/`span`
containers, `html_text_selector` names the text nodes (Oregon DOR and DFI SharePoint pages, the Utah relief page, the Virginia
ruling, the WA WAC and session-law pages, the RI budget bill).
