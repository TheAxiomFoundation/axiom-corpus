# Connecticut Section 12-700(a)(10) exact source unit

This additive scope repairs the source boundary for Connecticut's current
resident ordinary income-tax schedules. The earlier recovery scope retained
the complete Chapter 229 HTML body at
`us-ct/statute/12-700/block-1`. Child-path lookup therefore served the same
chapter-wide body for a request targeting Section 12-700(a)(10), exposing
unrelated sections and sibling provisions to downstream source-coverage
validation.

The standard official-document adapter now snapshots the Connecticut General
Assembly's current Chapter 229 HTML and uses an `anchor_range` extraction. The
range begins at subdivision (a)(10), the schedule for taxable years beginning
on or after January 1, 2024, and stops before subdivision (a)(11). It emits:

- `us-ct/statute/12-700-a-10`
- `us-ct/statute/12-700-a-10/operative-text`

The exact subsection identifier is intentionally flat rather than nested
under `us-ct/statute/12-700/a`. A partial additive scope must not make
subsection (a) resolve as though subdivision (10) were its only child.
Downstream RuleSpecs cite the body-bearing `operative-text` path directly.

The body-bearing child contains all four individual filing-status schedules,
the low-rate phaseouts, the recapture provisions, and the distinct
trust-or-estate rate in subparagraph (E). It excludes the chapter table of
contents, historical schedules in subdivisions (a)(1) through (a)(9),
subdivision (a)(11), nonresident subsection (b), annotations, and other
Chapter 229 sections.

Generate the artifacts without publication or database loading:

```bash
axiom_with_corpus_ingest_key uv run --extra dev axiom-corpus-ingest \
  extract-official-documents \
  --base data/corpus \
  --version 2026-07-26-ct-12-700-a-10 \
  --manifest manifests/us-ct-12-700-a-10-current.yaml
```

The protected wrapper supplies signing material only to the extraction
process. Private signing material is neither printed nor stored in the
repository. Release selection, publication, database loading, and downstream
RuleSpec pin changes remain separate reviewed steps.
