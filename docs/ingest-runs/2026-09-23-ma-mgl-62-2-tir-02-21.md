Currency. On the retrieval date the General Laws index page (retained as
`index.html`) stated that the site "includes all amendments to the General Laws
passed before May 31, 2026" and that it is an unofficial version of the official
edition. The manifest records this in its `source_scope_note`; `source_as_of`

Granularity. The official page asserts structure only to the section: the text
is one outer `<p>` nesting one unlabelled `<p>` per subsection, paragraph,
subparagraph and editorial note. Following the assertion-frontier rule proposed
in `docs/granularity-policy-proposal.md`, the section is one row, and the body keeps
each nested paragraph as its own line (98 lines, 28,696 characters): subsections
(a) through (i) (the section runs past (f) to nine subsections), the bracketed
publisher notes (`[ Text of section applicable as provided by 2021, 9, Secs. 8,
12 and 26. ...]`, the 2022 effective-date notes on (a)(2)(R) and (d)(1)(Q)), and
both dated alternatives of (d)(4) (effective until April 19, 2026; as amended by
2026, 65, Sec. 3 effective April 19, 2026). Subsection (c)(2)(a), the Part A
short-term capital loss deduction, is line 55.

Adapter changes (`src/axiom_corpus/corpus/state_adapters/massachusetts.py`):

- `parse_massachusetts_section` read the outer `<p>` with
  `get_text(" ", strip=True)`, which flattened every nested paragraph of a section
  into one line. It now emits one line per nested `<p>` or `<br>` line and
  concatenates inline markup as rendered (`(<i>I</i>)` reads `(I)`). Other block
  elements (`<div>`, `<blockquote>`, list items, table rows and the like) also
  break lines, and the cells of a table row are joined with a space, so a page
  that uses them never runs neighbouring blocks together. The thirteen retained
  chapter 62 section pages (the twelve recovery pages and `Section2.html`) use
  only `<p>` and `<i>` inside the section text, so that rule leaves their output
  unchanged. On the twelve chapter 62 section pages retained in the recovery
  scope, the new parser's text equals the old parser's text once whitespace is
  removed; only line breaks differ. The `Section N.` marker is stripped from the first non-bracketed
  paragraph, so a leading editorial note no longer blocks it.
- `extract_massachusetts_general_laws` takes `only_sections` (manifest option
  `only_sections`, a string or list). It keeps the part, title and chapter rows,
  fetches only the listed section pages, fails if a requested section is not
  listed on the chapter page, and appends `-sections-<numbers>` to the run id.

## Release caveat: chapter 62 navigation splits across the two statute scopes

The two `us-ma` statute scopes model chapter 62 differently, and a release that
serves both shows chapter 62 as holding only s. 2.

- This scope writes the container chain the adapter always writes, so
  `us-ma/statute/62/2` has parent `us-ma/statute/part-i/title-ix/chapter-62`,
  which chains through `.../title-ix` to the root `us-ma/statute/part-i`
  (levels 3 down to 0).
- The released `us-ma/statute/2026-07-13-recovery` scope (36 rows) stores its
  twelve chapter 62 sections as level-1 `document` rows at `us-ma/statute/62/N`
  with no `parent_citation_path`, each with two `block` children. No
  `us-ma/statute/62`, `us-ma/statute` or `us-ma` row exists in either scope, so
  the navigation builder's path-prefix fallback (`_resolve_parent_path` in
  `src/axiom_corpus/corpus/navigation.py`) finds no parent for them either.
- A local navigation build from both provisions files
  (`build-navigation-index --provisions <recovery> --provisions <this scope>
  --jurisdiction us-ma --doc-type statute --skip-supabase --no-rulespec-auto
  --output <scratch>`) gives 40 nodes and 13 roots: the twelve recovery sections
  (2 children each) and `us-ma/statute/part-i` (1 child). The chain ends at
  `.../chapter-62`, whose only child is `us-ma/statute/62/2`.
  `scripts/publish_corpus.py` builds navigation per scope with the same
  `build_navigation_nodes`, so the served tree would have the same shape.

So in a release selecting both scopes, the Part I > Title IX > Chapter 62
navigation branch holds only s. 2, while sections 3, 4, 6, 6L, 10A, 11A, 14, 16,
42, 54, 62 and 64 remain separate `us-ma` statute roots beside
`us-ma/statute/part-i`. `corpus.get_root_document_counts()`
(`supabase/migrations/20260910120000_root_document_counts.sql`) counts
navigation roots (`parent_path IS NULL`), so it would report 13 `us-ma` statute
root documents. The provision rows themselves and `validate-release` are
unaffected; this is how the two scopes look together, not a defect in either
one. This scope is deliberately not reshaped to match the recovery rows: its
parent chain is the official structure.

Durable fix (follow-up, not in this change): re-ingest the chapter 62 sections
the recovery scope carries through this adapter, as a full chapter 62 run or an
`only_sections` run listing 2, 3, 4, 6, 6L, 10A, 11A, 14, 16, 42, 54, 62 and 64,
and have the next `us-ma` selector select that scope in place of both
`2026-07-13-recovery` and this one. That swap needs a check that nothing
downstream cites the recovery scope's `us-ma/statute/62/N/block-K` rows, which
have no counterpart in the adapter's section-level rows. Whoever cuts the next
`us-ma` release decides between shipping the split tree and waiting for that
scope.

## Not done: leaf anchors for s. 2

Subsection paths such as `us-ma/statute/62/2/c/2/a` do not resolve yet. Running
`generate-anchors --target us-ma/statute/62/2` on the new provisions file fails
the collision gate (`duplicate anchor citation paths ... us-ma/statute/62/2/A`,
`.../B`, ...). The generator's outline ladder is the CFR order
`(a) (1) (i) (A)`, while chapter 62 drafts `(a) (1) (A) (i)`, so every
uppercase subparagraph is parsed as a new top-level node. The page also prints
two dated texts of (d)(4), which would share the path `.../d/4` under any
ladder. Anchoring this section needs a per-target outline ladder and a decision
on how dated alternatives are keyed, which is anchor-layer design work rather
than ingestion. Until then an encoding cites the section row
`us-ma/statute/62/2`; (c)(2)(a) is line 55 of its body.
