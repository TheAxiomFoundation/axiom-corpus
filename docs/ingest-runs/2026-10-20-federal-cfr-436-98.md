# 42 CFR 436 and 45 CFR 98: the two federal parts the September runs recorded as missing

Date: 2026-10-20. Branch `discovery/ingest-federal-cfr-436-98`, cut from `main`.
Jurisdiction `us`, document_class `regulation`, version base
`2026-10-20-federal-ecfr-closure`, which the eCFR adapter suffixes per part.

## Why these two

Both were recorded as absent by earlier runs and never ingested:

- **42 CFR 436** (Medicaid eligibility in Puerto Rico, Guam and the Virgin Islands).
  The 2026-09-10 Medicaid run recorded that part 435 is held and part 436 is not,
  and left the federal row `needs_review` with that finding.
- **45 CFR 98** (the CCDF regulation). The 2026-09-10 CCDF run recorded that the part
  is not in the corpus and named `extract-ecfr --only-title 45 --only-part 98` as the
  way to take it.

Confirmed absent before extracting: no coverage file named either part, and no
provisions file anywhere under `data/corpus/provisions` held a
`us/regulation/42/436` or `us/regulation/45/98` citation path.

## Duplicate-work check

`gh search prs "436"`, `gh search prs "45 CFR 98"` and `gh search issues "CFR 98"`
return no work on either part. Nine open PRs touch the eCFR adapter or CFR anchors
(#812, #828, #830, #831, #832, #841, #842, #844, #894); none ingests either part.
This run neither depends on nor duplicates any of them: it used the adapter exactly

## Reviewer judgments

1. **The as-of date is each title's own latest issue date, not today.** A first
   attempt with `--as-of 2026-10-20` failed with HTTP 404 from the eCFR API, because
   the API serves only dates it has issued: title 42's latest issue is 2026-10-13 and
   title 45's is 2026-10-06, both `up_to_date_as_of` 2026-10-16. Using the real issue
   date is also better provenance than using the run date. The two scopes therefore
   carry different as-of dates, which is correct and not an inconsistency.
2. **Appendices were not included.** `--include-appendices` rejects unsupported
   shapes, and four open PRs (#831, #844, and the appendix ingests #828 and #830) are
   still changing how part and subpart appendices are read. Neither part's appendices
   are taken here; a later run should add them once those land. Recorded rather than
   attempted.
3. **No adapter change.** Nothing under `src/` was modified. If any of the nine open
   eCFR fixes changes how sections are read, both scopes should be re-extracted before
   they are signed, because they are unsigned and nothing depends on them yet.
4. **20 CFR 416 was deliberately left alone.** The corpus holds only an Appendix K
   slice and the earlier 14-row deeming slice, so the bulk of the part is still
   missing, but PR #830 is actively ingesting part 416 appendices and PR #828 part
   404's. Taking the whole part now would collide with that work.
5. GitNexus MCP tools were unavailable, so no impact analysis ran.
